Практикум для 4-го курса. Сейчас доступен блок **«Детекция объектов»**.
Код демонстрационного ноутбука можно использовать при выполнении работы.

## Детекция: понять механику и обучить модель для нового домена

Основной маршрут — **01 → 02**. Сначала решаем короткие задачи на интерактивных
стендах, затем переносим детекторы на изображения клеток крови и сравниваем четыре модели.

| Ноутбук | Что делаем | Когда |
|---|---|---|
| [01 · Интерактивное демо](labs/01_detection/01_interactive_demo.ipynb) | Подбираем рамку под заданный IoU, управляем NMS и confidence, объясняем полученный результат | Вместе на занятии; по 2–3 минуты на задачу |
| [02 · Дообучение на новом домене](labs/01_detection/02_finetuning.ipynb) | Реализуем три блока с `TODO`, проверяем их, запускаем пилоты и сравниваем четыре модели | Основная работа: начало на занятии и обучение после него |

В ноутбуке 02 нужно самостоятельно реализовать три части:

1. Преобразование рамок в формат YOLO и горизонтальное отражение изображения
   вместе с рамками.
2. Заморозку backbone и выбор параметров для оптимизатора; проверить после шага
   обучения, что замороженные параметры не изменились, а обучаемые изменились.
3. Сопоставление предсказаний с разметкой по классу и IoU, подсчёт TP/FP/FN и
   автоматический отбор изображений val с ошибками.

Для каждого блока предусмотрены проверки. Пока `TODO` не заполнены, запуск
останавливается с `NotImplementedError`; это ожидаемая часть задания.
Циклы обучения четырёх моделей, загрузка весов и расчёт AP уже подготовлены.

Каждый студент сравнивает **все четыре модели**:

| Модель | Тип детектора | Роль в сравнении |
|---|---|---|
| SSDLite320 | Якорный | Компактная архитектура семейства SSD |
| YOLOv5n | Якорный | Исходная компактная YOLOv5 |
| YOLO11n | Безъякорный | Компактная YOLO более нового поколения |
| YOLO26n | Безъякорный | Новое поколение YOLO с оценкой через NMS |

Состав `SELECTED_MODELS` уже задан в ноутбуке. YOLOv5n здесь — исходная якорная
модель. YOLO26 использует ветвь one-to-many с NMS.

На занятии запустите **четыре пилота по 2 эпохи**, обоснуйте решение сохранить
общую настройку или изменить один параметр и при необходимости повторите пилот.
После проверки данных, обучения и валидации запустите все четыре модели
по **20 эпох** самостоятельно, заново от предобученных весов. Двадцать эпох —
учебный бюджет, а не обещание сходимости. Полную серию не требуется ждать на паре.

Нужны Python, NumPy и понимание IoU, precision/recall, валидации и теста.
Не требуется писать детектор с нуля. Важны корректное сравнение и объяснение
результата, а не самая высокая метрика в группе.

## Быстрый запуск

**Google Colab.** Откройте нужный ноутбук:

- [01 · Интерактивное демо в Colab](https://colab.research.google.com/github/AndreySheka/applied-ai/blob/main/labs/01_detection/01_interactive_demo.ipynb)
- [02 · Дообучение в Colab](https://colab.research.google.com/github/AndreySheka/applied-ai/blob/main/labs/01_detection/02_finetuning.ipynb)

Чтобы сохранить свои изменения, выберите **Файл → Сохранить копию на Диске**.
Первая ячейка устанавливает зависимости; ноутбуки самодостаточны и не требуют
клонирования репозитория. Для обучения включите GPU в **Среда выполнения →
Сменить среду выполнения**. Интерактивное демо работает на CPU; длинное обучение
на CPU существенно медленнее, поэтому для него предпочтительна доступная GPU.

**Локально с conda и NVIDIA GPU.** Скачайте репозиторий и подготовьте окружение:

```bash
git clone https://github.com/AndreySheka/applied-ai.git
cd applied-ai
conda env create -f environment.yml
conda run -n applied-ai python -m ipykernel install --user --name applied-ai --display-name "Python (applied-ai)"
./start_demo.sh
```

Если окружение `applied-ai` уже подготовлено, достаточно `./start_demo.sh`.
Для CPU, Windows и других вариантов см. [настройку среды](docs/SETUP.md).

Запускайте ячейки сверху вниз. Для ползунков нужен подключённый Python kernel:
просмотр файла на GitHub сам по себе код не выполняет. Стенды также доступны
обычным вызовом функции с параметрами.

## Данные и вычисления

В демо используется Penn–Fudan с пешеходами. Для дообучения выбран другой домен —
BCCD, изображения клеток крови с классами `RBC`, `WBC`, `Platelets`, которых нет
в исходной COCO-голове детектора. После очистки используем **205 train / 86 val /
72 test**. Перед обучением просмотрите изображения и распределение классов.

Данные и веса загружаются автоматически с проверкой SHA-256; для первого запуска
нужен интернет. Их не нужно добавлять в Git. Сравнивайте все четыре модели на одних
изображениях и по одному правилу расчёта метрик; test открывайте после фиксации
настроек. Разница между архитектурами и поколениями не объясняется одним только
наличием якорей: у них также различаются устройство сети, подготовка входа и обучение.
Используем общий учебный бюджет и явные настройки, поэтому результаты не
воспроизводят официальные таблицы качества моделей.
