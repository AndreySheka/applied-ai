# Запуск и устранение неполадок

## Блок объектной сегментации

Ноутбуки находятся в `labs/02_segmentation` и используют ту же среду, что детекция.
Для демо достаточно CPU; для Mask R-CNN и YOLO11-seg с обучением включите GPU.
Они самодостаточны: можно отдельно загрузить `.ipynb` в Colab. Данные и веса сохраняются
в `segmentation_lab_data`; начальная загрузка составляет около 228 MiB без библиотек.
Три блока `TODO` основной работы намеренно останавливают запуск до реализации.
`RUN_PILOT`, `RUN_LONG`, `RUN_TEST` выключены по умолчанию.
Не поднимайте порог пикселя у результата YOLO в этом API: он уже бинарный;
ползунок вероятности в демо использует выход Mask R-CNN.

В обновлённом демо сегментации **6 стендов и 25 микрозаданий**. После получения новой версии
перезагрузите ноутбук с диска и выполните **Restart Kernel and Run All Cells**.
У каждого стенда один рисунок: статичный пример заменяется живым выводом при запуске.
Порог MATCH IoU меняет пары и счётчики, а не пиксели. Начните со сравнения 0.50 и 0.55
для слитой маски. Для сдвинутых масок доступен отдельный ползунок сдвига.

## Colab

### Лабораторная 04: визуальные представления

Для [демо 04](../labs/04_visual_representations/01_interactive_demo.ipynb) выберите в меню Colab «Среда выполнения → Сменить среду выполнения → Runtime version 2026.07». При возможности включите GPU T4. Первый запуск установит Transformers 4.51.3 и, если прежний запуск изменил виджеты, восстановит ipywidgets 7.7.1; затем перезапустите сеанс и выполните ноутбук сверху. Ячейка покажет версии и доступность CUDA. Полный `requirements.txt` лабораторной 04 предназначен для отдельного локального Python 3.11 окружения; установка его в Colab заменяет работающую GPU-сборку PyTorch и штатные виджеты. Подробности и прямая ссылка на Colab — в [README лабораторной 04](../labs/04_visual_representations/README.md).

У разных лабораторных свои установочные ячейки. Применяйте инструкцию нужной лабораторной и не запускайте установку пакетов из нескольких работ в одном сеансе Colab: фиксированные версии могут противоречить друг другу.

Каждый ноутбук можно загрузить отдельно. В работах с установочной ячейкой выполните
её до остальных ячеек. Если пакеты были обновлены после импортов, перезапустите
среду и начните сверху. Выбор версий и настройку виджетов уточняйте в README
конкретной лабораторной.

В GitHub видны текст и сохранённые обычные рисунки. Интерактивность работает
только в Jupyter/Colab с живым ядром. Когда вместо элементов управления виден
текст вида `VBox(...)`, используйте обычный вызов соответствующей функции или
перезапустите ядро после установки `ipywidgets`.

Основной маршрут — интерактивное демо 01, затем дообучение 02. Для обучения
включите GPU до выполнения импортов. Colab может временно не предоставить GPU:
в таком случае сначала выполните демо, подготовку данных и просмотр разметки.
Длинные запуски перенесите на сеанс с GPU или локальный компьютер с NVIDIA.

## Как проходить интерактивное демо

Перед каждым из пяти стендов прочитайте цель, короткое объяснение и легенду.
Сначала предположите результат, затем проверьте его ползунками и выполните
задания под рисунком. Первые три стенда используют заданные рамки, последние
два — реальные предсказания YOLO11n. Обучение в демо не запускается.

В стенде «Пирамида изображений» один снимок обрабатывается в двух размерах.
Сначала выполните ячейку подготовки предсказаний, затем сравнивайте отдельные
масштабы и объединение. Изменение confidence и межмасштабного NMS использует
уже рассчитанные рамки и не запускает модель заново.

## Переключатели обучения в ноутбуке 02

Сначала оставьте `RUN_PILOT=False`, `RUN_LONG=False` и `RUN_TEST=False`.
Заполняйте три блока с `TODO` по порядку и выполняйте проверки после каждого.
До этого запуск всех ячеек остановится на `NotImplementedError` с названием
недописанной функции. Это ожидаемое поведение шаблона, а не ошибка установки.
Готовые циклы обучения начнут работать после реализации и проверки учебных блоков.

Сначала реализуйте преобразование рамок и отражение изображения, затем настройку
обучаемых параметров и проверку одного шага, затем сопоставление рамок для
TP/FP/FN. Пограничные случаи проверяются на небольших примерах без длинного
обучения. Автоматический отбор ошибочных val-кадров используйте после пилотов.

1. После прохождения проверок заполните `STUDENT_ID` и `HYPOTHESIS`. В `SELECTED_MODELS` уже заданы четыре
   обязательные модели: SSDLite320, YOLOv5n, YOLO11n и YOLO26n.
   Включите `RUN_PILOT=True`, повторно выполните ячейку конфигурации и ячейку
   пилота: все четыре модели последовательно пройдут по 2 эпохи.
2. Проверьте пилоты и обоснуйте решение сохранить общую настройку или изменить
   один параметр. При необходимости повторите пилот и запишите `PILOT_NOTE`
   и `FINAL_CONFIG_NOTE`.
   Для самостоятельной части выключите `RUN_PILOT`,
   включите `RUN_LONG` и повторно выполните конфигурацию и длинный запуск.
   Все четыре модели начнут по 20 эпох от исходных предобученных весов.
3. После сравнения на val и фиксации настроек включите `RUN_TEST` для итогового
   теста всех четырёх моделей. Остальные флаги можно оставить выключенными, чтобы не возвращаться
   к этапам обучения.

В сравнении показаны четыре отдельные кривые loss и общий график AP.
Ползунок confidence управляет предсказаниями всех четырёх моделей на одном
изображении; рядом показана разметка. Значения loss разных моделей имеют разные шкалы.

В одной сессии уже выполненные функции остаются доступны. После перезапуска ядра
снова выполните подготовительные ячейки. Завершённые запуски с тем же протоколом
загружаются из сохранённых результатов; незавершённые автоматически не продолжаются.
Сохраните прерванный опыт отдельно и начните новый с другим `STUDENT_ID`.

## Локальная conda: NVIDIA, Linux или Windows

`environment.yml` закрепляет Python 3.11, PyTorch 2.5.1+cu121 и torchvision
0.20.1+cu121. CUDA Toolkit отдельно устанавливать не требуется; нужен подходящий
драйвер NVIDIA.

```bash
conda env create -f environment.yml
conda activate applied-ai
python -m ipykernel install --user --name applied-ai --display-name "Python (applied-ai)"
```

Linux/macOS-терминал с совместимой средой: `./start_demo.sh`. В Windows можно
открыть Anaconda Prompt и после активации выполнить из корня репозитория:

```bash
python -m jupyterlab --ServerApp.ip=127.0.0.1 labs/01_detection/01_interactive_demo.ipynb
```

В интерфейсе выберите **Python (applied-ai)**. Скрипт запускает сервер, выбирает
окружение и открывает демо; ячейки нужно выполнять самостоятельно. Остановка
сервера — `Ctrl+C` в его терминале.

## Локально на CPU

Для Linux/Windows создайте чистое окружение и установите CPU-сборку PyTorch:

```bash
conda create -n applied-ai-cpu -c conda-forge python=3.11 pip
conda activate applied-ai-cpu
python -m pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python -m ipykernel install --user --name applied-ai-cpu --display-name "Python (applied-ai-cpu)"
python -m jupyterlab --ServerApp.ip=127.0.0.1 labs/01_detection/01_interactive_demo.ipynb
```

На macOS установите `torch==2.5.1 torchvision==0.20.1` из обычного PyPI без
CUDA/CPU index, затем остальные зависимости. Ноутбуки используют CPU, если CUDA
недоступна; MPS отдельно не задействован. Для принудительного CPU задайте
`DEVICE = 'cpu'` в ячейке импортов.

На CPU доступны все стенды, подготовка BCCD и просмотр рамок. Для намеренного
короткого пилота дополнительно включите `ALLOW_CPU_TRAINING=True` и `RUN_PILOT`.
Это снимает защиту от случайного запуска; обучение на CPU может быть медленным.
`RUN_LONG` оставьте выключенным и выполните длинную часть позже на GPU.

## Данные и переносимость

Ноутбуки не читают файлы с преподавательского компьютера. Без специальных
настроек они создают `detection_lab_data` в рабочей папке. `start_demo.sh`
задаёт общую папку `.cache/detection` в корне репозитория. Обе исключены из Git.
Чтобы использовать уже скачанные данные, перед запуском можно задать
`DETECTION_LAB_ROOT` со своим путём. Данные нового домена находятся во вложенной
папке `domain_transfer` этого кэша.

Первая загрузка BCCD — около **8 МБ**. Предобученные веса загружаются
для четырёх моделей. Для YOLOv5n ноутбук автоматически скачивает также код
модели; вручную клонировать репозиторий не нужно. Установка PyTorch и других
библиотек занимает значительно больше места, чем изображения этого набора.
Для длинного обучения также нужно место под собственные веса, журналы и результаты.

Результаты сохраняются в `artifacts/domain_transfer/<ID-хэш>/` относительно
рабочей папки. В Colab файлы обычной среды исчезают при её сбросе. До длинного
запуска задайте `ARTIFACTS` внутри подключённого Google Drive либо скачайте
результаты до завершения сеанса. Сохраняйте настройки, журналы и свои обученные
веса вместе: одного скриншота метрики недостаточно для повторного сравнения.

## Если интерфейс не открывается

Используйте версии Jupyter, Tornado и ipykernel из файлов окружения вместе.
После обновления пакетов остановите старый сервер, запустите его заново и
перезапустите ядро ноутбука. Сервер запускается локально на `127.0.0.1`.

Сообщение «порт занят, пробую следующий» означает, что другой сервер уже работает.
Откройте адрес из вывода нужного процесса. `Skipped non-installed server(s)`
относится к необязательным языковым серверам и не мешает ноутбукам.

Если не появились ползунки, проверьте наличие `ipywidgets` в окружении ядра и
`jupyterlab_widgets` в окружении сервера. При установке всех зависимостей в одно
окружение они устанавливаются вместе. Перезапустите ядро и выполните ячейки сверху.
В Colab сначала выполните установочную ячейку, которая включает менеджер виджетов.
