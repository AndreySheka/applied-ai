# 08 · Оптический поток

Лабораторная к лекции 9. Вы научитесь задавать направление потока, восстанавливать первый кадр, проверять локальную наблюдаемость, переносить поле между разрешениями и оценивать ошибки только там, где известен ответ.

## Порядок работы

1. `01_interactive_demo.ipynb` — девять стендов: направление/warping, наблюдаемость LK, пирамида LK, итерации Horn–Schunck, resize поля, EPE/маски, Farnebäck/DIS, обратная согласованность и перенос информации между кадрами. В каждом по восемь управляющих параметров. Теория расположена перед стендом, задания — отдельной ячейкой сразу под ним. Для каждого сначала запишите прогноз, затем измените параметры и объясните результат. Ориентир: 70–90 минут; можно пройти демо отдельным занятием.
2. `02_flow_experiment.ipynb` — шесть TODO с открытыми тестами, своими контрпримерами и сравнением Farneback/DIS. Ориентир самостоятельной работы: 150–190 минут. Это время размышлений, реализации и отчета; вычислительная часть занимает секунды/минуты на CPU.
3. Сверьте сдачу с [критериями](ASSESSMENT.md).

## Запуск

Python 3.10+, Jupyter Notebook/JupyterLab; пакеты `numpy`, `matplotlib`, `opencv-python`, `ipywidgets`. Если в окружении уже есть подходящий OpenCV, второй пакет OpenCV ставить не нужно. Нужны функции `calcOpticalFlowFarneback` и `DISOpticalFlow_create`; notebook проверяет их наличие. Используется один CPU thread, GPU и веса моделей не требуются.

Откройте ноутбук, выберите Python kernel и выполните ячейки сверху вниз. В основном задании `NotImplementedError` обозначает место вашей реализации. Каждый notebook содержит собственные вспомогательные функции; приватные файлы преподавателя не нужны. Widgets должны быть включены в Jupyter frontend. Проверенная локальная среда: Python 3.11.16, NumPy 2.4.6, Matplotlib 3.11.0, OpenCV 5.0.0, ipywidgets 8.1.9. Все вычисления выполняются на CPU, одним потоком OpenCV. Браузерная проверка Colab этой редакции не выполнена; отдельная инструкция загрузки не является подтверждением проверки Colab.

Синтетические пары создаются локально по фиксированным seeds. Реальная ветка скачивает sample OpenCV (~8.1 МБ) по закрепленной ссылке и проверяет SHA-256; повторно используется временный кэш. Без сети эту ветку можно выполнить позднее. Она не участвует в выборе параметров и основной оценке. CSV, JSON и рисунки записываются в `results/` относительно рабочей папки kernel.

## Как устроены стенды

Всего 72 управляющих параметра, без учета кнопок повтора и сброса. Ползунки применяются после отпускания. В сравнении Farnebäck/DIS настройки применяются кнопкой «Рассчитать»; над результатом видно, соответствуют ли ему текущие параметры. Каждый стенд можно вернуть к исходным настройкам.

Изменяйте одну причину за опыт. Смотрите одновременно на вход, промежуточный результат и число: EPE, residual, собственные значения, coverage или ошибку восстановления. Временные замеры локальны и зависят от оборудования. Демо показывает учебные синтетические пары; это не benchmark реальных съемок.

## Что фиксируем

Forward flow `f12(x)` задан на сетке первого кадра: точка приходит в `x + f12(x)` второго. Реконструкция: `I1_hat(x) = I2(x + f12(x))`. Ось x направлена вправо, y вниз; единицы — пиксели. Backward flow живет на сетке второго кадра, поэтому простое отрицание массива обычно неверно.

GT-valid означает совместно видимые исходные пиксели. Маска общая для всех методов. Forward/backward consistency — дополнительная диагностика; ею нельзя отбирать «удобные» пиксели для основной EPE.

Val и test используют разные seeds и заранее заданные смещения. После выбора метода по pooled val EPE создается `selection_locked.json`; перед открытием test проверяются совпадение параметров, seeds, версии OpenCV, числа потоков и абляции. Изменение протокола останавливает запуск. На test сравниваются оба метода и заранее объявленная абляция половинного разрешения выбранного метода. Векторы возвращаются в исходные пиксели. Дополнительную настройку по test не делать.

## Что сдать

Два заполненных ноутбука либо основной notebook и таблицу минимум 18 опытов демо (по два на каждый из девяти стендов); собственные проверки; `results/*.csv`, конфигурацию и ключевые рисунки; разбор ошибки и ограничений. Не нужны скачанное видео и временный кэш.

Это учебная синтетика с точной геометрией, а не benchmark Sintel/KITTI. У реального клипа нет используемой GT; photometric MAE и median flow не являются EPE или доказательством правильной оценки движения камеры.

Источники: [OpenCV optical flow](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html), [Farneback](https://www.ida.liu.se/ext/WITAS-ev/Computer_Vision_Technologies/Papers/scia03_farneback.pdf), [DIS](https://arxiv.org/abs/1603.03590).

Предустановленные PyTorch/CUDA и ipywidgets Colab сохраняются. Все вычисления этой работы идут на CPU; GPU не ускорит стенды. После первого перезапуска выполните ячейки сверху.
